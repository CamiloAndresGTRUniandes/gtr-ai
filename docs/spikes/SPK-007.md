# SPK-007 — SQLite persistence

**Status:** OPEN — partial Apply/Verify evidence; not closed

## Technical question
Can the proposed SQLite persistence satisfy the master prompt requirements?

## Verified results
Both `node:sqlite` and `better-sqlite3` 13.2.0 loaded `sqlite-vec` 0.1.9, passed FTS5 matching, inserted synthetic vectors using integer-compatible row IDs, and returned the expected nearest row. Verify recorded approximately 0.0116 ms warm p95 over 1,000 synthetic queries per binding. This is a narrow smoke test, not a workload benchmark.

## Evidence
Apply evidence: `../../.spike-workspaces/linux-x64/evidence/877d9948-73be-4cf5-a07b-018fa0a62e5f/`. Historical WAL, rollback, migration and backup evidence remains under `../../evidence/` and `../benchmarks/`.

## Remaining acceptance criteria and limitations
Migration and backup/restore behavior with the selected binding, disk-scale concurrency, LangGraph checkpoint compatibility, native Windows/Linux/macOS behavior, and a single supported binding strategy remain unverified. LangGraph resolved a nested `better-sqlite3` 12.11.1, so the evidence does not establish one shared binding.

## Recommendation / fallback
Evaluate `node:sqlite` first for the target runtime, but defer selection until checkpoint, vector extension and OS matrix tests complete.

## Security and licensing
No credentials, paid requests or external writes were used. Extension integrity, install scripts and transitive licenses require review.

## Related decisions
SPIKE-ADR-01 remains a candidate with selection deferred; no new ADR is accepted by this Apply/Verify iteration.
